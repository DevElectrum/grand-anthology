# R8.4 C3D2 + C4: two large implementation batches, one integrated acceptance campaign

**Status: design approved for planning only, not implemented.** Prepared 2026-11-04. Experimental game branch `xgba/a2-collection-lab` at documentation baseline `ebcd6aa7`; last C3D1 code `33169f0d` passed both controller interfaces with real Save3, independent exact-record audit, and fresh XGBA Continue ([run 41811066427](https://github.com/DevElectrum/grand-anthology/actions/runs/41811066427)). Pinned XGBA R8 `4e0f59185e2c7d7ed5333d8adc20e8d3ad94d05c`. Preserve game `main`, Mosaic, frozen E7, real saves, native ABI and current 16 MiB A2 E6 journal. We are finishing R8.4 for Sinnoh, not developing a new emulator or save schema.

## Current source facts that drive architecture

1. `src/save.c` already provides validated RAM-only `XgbaA2GameMoveGlobalBoxMon`, `XgbaA2GameSwapGlobalBoxMons`, `XgbaA2GameDepositPartyMonGlobal` and `XgbaA2GameWithdrawGlobalBoxMon`. The checked global identity is `u16 globalBox = 0..111`, `u8 slot = 0..29`; `TOTAL_BOXES_COUNT == 14` remains a native sentinel.
2. Both PC engines' legacy `MoveMon` / `SetMovingMonData` remove the source immediately into a UI-owned held-mon buffer. Their R8 group-boundary scroll explicitly rejects `IsMonBeingMoved()`; reopening the UI cannot preserve that pointer/carry safely. **Do not remove this guard** without a replacement state machine.
3. SwSh `Task_BulkRelease` and `BulkReleaseEligible` currently operate on 30 slots with `u32 sBulkReleaseMask`, `u8 sBulkReleaseCount` and `u8 sBulkKeptCount`. Its R8 variant uses a live bag snapshot and applies all item returns before deleting *within the current box*. That is not a cross-collection transaction. Classic does not expose an equivalent bulk-clear workflow.
4. Both engines' single-release `AtLeastThreeUsableMons` and `RunCanReleaseMon` inspect only 14 resident boxes. Single `ReleaseMon` may discard the Pokémon even if `AddBagItem` fails. On unavailable R8 collection, some global count helpers return zero, which **must never be interpreted as an empty collection** for deletion eligibility.
5. Bulk eligibility already excludes marked favorites (marking bit 3), eggs, mail, legendary/sub-legendary/mythical species including National Dex base forms, and restricted field-move owners. Preserve this policy. Shiny alone is deliberately *not* protection. Do not silently alter native-only behavior or apply blanket bans to intentionally confirmed individual releases.

## Design choice: safe virtual carry, not pointer carry

**Chosen:** add one shared R8 remote-transfer transaction, initiated from a highlighted boxed Pokémon as `Transfer` / `Move to another box`. Show the original Pokémon as a *virtual held source* while selecting a global destination box and exact destination slot. R/L navigates groups, current 14-box chooser/box grid stays familiar, and both PC frontends call the same backend. Local native drag within one group remains unchanged. When the UI must be torn down and rebuilt, source ownership stays in canonical R8 collection, not a UI sprite or the legacy held-mon buffer. Transfer to an empty slot is Move; an occupied target asks for explicit Swap confirmation. B cancels at every level without mutation. Box 112 → Box 1 wrap is available.

**Rejected:** permitting ordinary `sIsMonBeingMoved` across the page boundary (source already purged); stashing raw `BoxPokemon *` across resident-page changes; committing source removal before a destination is selected; silently dropping into the first free slot when an occupied destination was selected. These create loss/duplication risks and conflict with UI teardown.

### Batch C3D2: complete cross-group Move + Swap in both interfaces

**Single coherent production change, not an incremental diagnostic series:**

- Add an R8-only transfer coordinator (suggested `src/xgba_r8_pc_ops.[ch]`) with a typed, validated pending operation: source global box, source slot, full **80-byte encrypted snapshot**, original selected group, chosen destination global box/slot, operation kind, state and generation/health witness. No raw pointer persists between frames or reopens. Store only short-lived scratch in a specifically reserved, alignment-checked slice of volatile R8 RAM, disjoint from the existing eight-page collection, its known bag scratch and future C4 bitset. This scratch is **never** written to native save or E6.
- On begin, require healthy collection and nonempty source; copy exact bytes but **do not clear source**. Distinct source/destination IDs are mandatory. Preview may read all 112 boxes from canonical RAM without selecting an on-disk page. Changing the displayed native group is allowed only through existing checked R8 RAM synchronization.
- Commit re-reads and byte-compares original source against the snapshot, checks source and destination bounds/health, validates the destination as empty for Move or occupied for Swap, checks mail/unsupported field operations, then calls the established checked RAM-only move or swap backend. Any failed preflight, changed source, self-move, invalid index, full/occupied destination, missing R8 hardware or modal cancellation gives an explicit reason and **zero record mutations**. A successful Move makes exactly the source slot empty and destination equal the original 80 bytes. A successful Swap exchanges exactly those two 80-byte records, including held items and markings.
- The UI never invokes legacy `SetMovingMonData` for the remote path. On success, discard the pending state and rebuild destination icons once. On cancel or unexpected UI teardown, discard pending state and leave source unchanged. No save/region transition while a transaction is pending. Do not change standard local Move/Shift, party deposit/withdraw (C3D1 accepted), or native-only/A2-only build semantics.
- Give Classic and SwSh the **same** user-visible route and failure wording, with frontend-specific title/menu/grid adapters only. Do not add another separate storage backend for the second frontend. Remote Transfer must be possible without button-spamming 111 boxes; reuse L/R group previews and 14-box selection.

**C3D2 integration acceptance, one two-frontend matrix:** host preflight unit tests and real controller in both UIs for 14↔15, 28↔29, 112↔1, remote occupied Swap, exact-slot Move, cancel before/after group preview, wrong source snapshot, source disappeared/changed, full box, absent capability, item/marking preservation and local drag regression. Real Save3 on a disposable Save2 clone, new XGBA process cold Continue, independent CRC-pinned 3,360-slot auditor: exactly the expected two slots differ for a remote Move/Swap; all other records bit-identical. Reject any false-positive GUI witness. One bounded performance sample. If it passes, close C3D2; no re-test of the unchanged C3D1 implementation.

## Batch C4: collection-wide destructive + held-item safety

**Single coherent production change after C3D2, not small ad hoc menu patches:**

1. **Shared protection/eligibility engine.** Give both PC interfaces a checked collection-wide `CanRelease`/release-plan API that returns status + reason, never a misleading zero count on unavailable storage. Count party + *all 112 boxes*; preserve at least three owned non-egg Pokémon after the entire proposed deletion set. Preserve the distinct last-usable-party rule. For restricted field moves (Surf, Dive and map-specific requirements), ensure each required move survives **outside the whole selected set**, not merely outside each candidate individually. Protected favorites/legendary/mythical/eggs/mail are excluded from bulk and Clear; shininess alone is not a veto. A deliberately chosen single release requires its own explicit confirmation and protection-aware messaging, not a hidden bulk-policy bypass; require an extra explicit confirmation for intentional release of otherwise protected species and require unfavoriting if marked. Both interfaces use the same rules. Item return must be safe for single release as well as bulk.
2. **Global selection representation and UI.** Replace the 30-slot mask as the authoritative R8 selection with a 3,360-bit bitmap (**420 bytes**) keyed by absolute global box and slot; counters are at least `u16` (up to 3,360), not `u8`. Retain the familiar current-box selection interface, but extend scope intentionally: **This Box (30)**, **This Group (420)**, and **All Boxes (3,360)**. No implicit all-collection delete from the normal Clear Box entry. Both frontend menus show selected, protected/skipped, kept and held-item return counts, then a two-stage confirmation for group/all-collection purges. Selections in a different group remain explicitly represented, not discarded on UI reopen. B/No does not mutate any Pokémon, bag or saved generation.
3. **True item transaction.** Preflight every selected Pokémon and held item, including repeated item IDs, bag pockets/stacking/slot capacities, mail and key-class constraints. Treat the **actual bag layout and `gBagPockets` pointers** carefully: a shallow copy + `AddBagItem` on globals is not a side-effect-free capacity check. Design a checked dry-run against scratch-backed pocket contents, or a real snapshot/restore transaction whose allocation and any external side effects are verified. Fail-closed in incompatible item/bag modes (e.g. Battle Pyramid). Stage a complete bag outcome **before any Pokémon record is erased**, apply/verify returns, and only then clear all selected sources without further fallible operations. On any failed item return/validation, restore bag and leave every Pokémon intact; no silent partial clear.
4. **Shared single-release fix.** Route single release in Classic and SwSh through the same checked global eligibility + item transaction as bulk. Remove 14-box-only release correctness assumptions for R8, but preserve native-only controls. Do not call legacy `ReleaseMon` as an unchecked deletion fallback if the shared preflight rejects.
5. **Held-item move/swap across groups.** Add explicit `Transfer Item` from a highlighted boxed Pokémon to a selected Pokémon in another global box, with direct checked mutation of both held-item fields as one RAM transaction (optionally Swap Items when target already holds an item). Reject mail/key-class duplication, invalid item/target, missing collection or source identity change. Keep the existing *local* Move Items UX. Do not carry item pointers across UI rebuild; never create a duplicate copy of a key-class item. Bag-to-mon and mon-to-bag transitions must retain their own checked quantity and full-pocket semantics.
6. **No hot-path global scan.** Run a bounded up-to-3,360-record eligibility/count scan on entering a destructive confirmation or preparing a transaction, not every frame, cursor change or box redraw. No 3,360 simultaneous sprites. Use the R8 scratch allocator with compile-time overlap/bounds checks rather than another untracked literal pointer. For operations covering multiple groups, mutation is RAM-only until the user's ordinary A2 whole-game Save. R8 RAM remains volatile; E6's existing cohort transaction is the sole crash-recovery authority.

**C4 integration acceptance, one two-frontend matrix:** full/empty box and 0/1/3/3359/3360 occupied collection; selection count boundaries 30/31/255/256/420/421/3359/3360; favorite, base-form legendary and mythical, egg, mail, shiny, HP/status/field moves, three-mon protection, sole Surf/Dive owner, multiple candidates each possessing the only required move; full bag and duplicate stack return, same/different item pockets, held key-class constraints; item transfer to empty/occupied target; cancellation at each confirmation; healthy→unavailable collection, source-record mismatch and absence of R8. Verify explicit refusal with no RAM/disk change. Real controller scripts for both UIs must perform selected-box, group and full-collection preview/confirmation, single protected handling, full-bag rejection and successful held-item returns. Save twice on disposable copies, independent **all-3,360-record** before/after expected-delta audit and new-process cold Continue showing exact surviving records, party and bag. Clean up every test ROM/save; never publish artifacts.

## Engineering delivery and regression cadence

**Two implementation batches, not a dozen serial test gates.** Stage C3D2 in one cohesive feature branch/change set (shared coordinator, both frontends, host tests, controller scripts, auditor expectations), run one full exact-head two-frontend CI matrix; review only actual failure evidence and issue one grouped correction if necessary. Stage C4 likewise as one cohesive change set, then run one **combined** real controller/Save/cold-audit campaign across both C3D2 and C4. Rebuild the ROM once per frontend and reuse cloned disposable E6 saves across test scenarios. Verify normal/A1/A2/R8 link and ROM packaging at the combined acceptance gate. Source assertions and controller success are different forms of evidence; both must pass.

**Static/resource budgets:** original 14-box ABI and native storage layout unchanged; 8×34,144 = 273,152-byte R8 collection; 3,360×80 = 268,800 boxed record bytes; selection bitmap 420 bytes; one 80-byte transfer snapshot per pending operation; no additional on-disk metadata; zero E6 I/O during box navigation/move/preview/bulk transaction until actual Save; at most existing two 34,144-byte RAM copies on a group switch. C4 scan bounded to one full collection per preflight/confirmation, never per frame. Measure real emulator frames/cycles and wall time separately; no invented performance promises. Save writes only the A2 journal's changed groups.

**Non-negotiable failure/stop conditions:** missing R8 capability, unhealthy collection, invalid source/destination, inconsistent bag pointers, unsupported mail/key item semantics, source mismatch, protection breach or missing save provenance means abort without modifying records. Continue autonomous engineering only when explicitly authorized to implement. No main merge, playable ROM or player-save mutation before C3D2, C4 and C5 recovery/cross-region gates are green. After a green C4, C5 is the **last** R8.4 safety/release pass before beginning Sinnoh map/story development, not another design loop.

## Architect vs. adversarial review summary

- *Architect*: Existing checked RAM APIs and 4 MiB arena mean a remote transfer should be a small, source-anchored operation. A 420-byte selection bitmap makes collection purge cheap. One shared engine removes Classic/SwSh disagreement.
- *Adversary*: Legacy grab clears source, UI reopen destroys ownership, box chooser mutates cursor, absent collection looks empty to some count callers, 8-bit bulk counters overflow, `AddBagItem` failure can delete an item-bearing Pokémon, independently eligible release candidates can collectively remove the final field-move user, and a copied bag may not isolate `gBagPockets` pointers.
- *Resolution*: Never purge a remote source until validated commit; never delete a single Pokémon until all bag returns and global protections are confirmed; verify exact on-disk deltas after a fresh-process save/cold-load. The UI may be rebuilt; the transaction source and protection decisions must survive or fail closed. Preserve the older proven release/compatibility behavior outside R8.
