# Grand Anthology R8.4: complete 4 MiB RAM integration
Design approved for planning only, 2026-11-02 UTC. No implementation code or release changes in this checkpoint.

## Starting facts, baselines, and protected repositories
- XGBA R8 source: `DevElectrum/xgba@xgba/r8-4mib-ram`, verified HEAD `4e0f59185e2c7d7ed5333d8adc20e8d3ad94d05c`. Core suite 16/16 passed in https://github.com/DevElectrum/xgba/actions/runs/41439796163. R8 maps additional 4,194,304-byte volatile RAM at CPU `0x20000000..0x203FFFFF`. E6-only opt-in descriptor at ROM offset `0x0FFFFF00` is ASCII `XGBARAM8` + little-endian 32-bit version 1 + size 0x00400000. Ordinary E7 is FROZEN at `9aa5e11e08274e5df09379be8f088e7e6db8f139`.
- Anthology: `DevElectrum/grand-anthology@xgba/a2-collection-lab` HEAD `b266480df8664b1ec4769ddfab05571873e5940c`. A2 source tests passed https://github.com/DevElectrum/grand-anthology/actions/runs/41410932976. Real E7 headless Save1/Continue/Save2/Continue, counter 1 then 2, metadata generation 1 then 2 and alternating native slots passed https://github.com/DevElectrum/grand-anthology/actions/runs/41409715346. **These were not populated cross-page gameplay tests.**
- Never alter or merge main, Mosaic, accepted E7, XGBA release branding, user's live ROM/save, or existing experimental A2 save without explicit creation of a separate disposable output. Keep standard and A1 builds unchanged and build R8 with isolated object directories.
- Scope of R8.4: complete adoption of R8 RAM for the **existing 112-box system**, all gameplay access/capture/move/count/held-item semantics, continuous navigation, coherent full-game persistence, runtime compatibility and headless verification. Existing bag remains global and its native ABI remains fixed. Building a *larger-capacity* bag schema is separately scoped to A2.5/R8.5 because it requires a NEW versioned save schema; R8.4 must provide correct bag interactions, held-item return safety and a clear integration seam.

## Non-negotiable memory and save ABI
1. `sizeof(struct BoxPokemon)==80`; `sizeof(struct PokemonStorage)==34144`; `TOTAL_BOXES_COUNT==14`; `IN_BOX_COUNT==30`. Preserve exact native SaveBlock1/2/3, PokemonStorage offsets, 128 KiB Flash slots, 56-byte A2 metadata and E6 16 MiB envelope. 8 x 34144 = **273,152 bytes** for all 112 boxes / 3,360 slots, ~6.51% of 4 MiB, leaving 3,921,152 bytes unallocated before other R8 buffers. Do not put collection-wide arrays in original 256 KiB EWRAM or enlarge linker native section.
2. One **volatile RAM collection** at a pinned `0x20000000`-relative arena offset with compile-time alignment and end assertions. Treat game pointers into R8 RAM as outside the ASLR-moved native SaveBlock region. On every boot/reload, rehydrate from the *selected CRC-verified A2 E6 cohort*; R8 RAM is never a save file, source of recovery truth, or protected backup.
3. Keep original 14-box `gPokemonStoragePtr` as the **native compatibility window** for the currently displayed group. Other seven groups live in the 273,152-byte RAM collection. For the active group, direct legacy writes can update the native window; synchronize that window into its R8 counterpart before global scan, page group change, save, snapshot, region transition or any path requiring canonical visibility. A clean group load copies R8 into the 14-box native window. RAM-to-RAM/native copies must never read or write E6 while navigating boxes.
4. Provide a single storage facade with `globalBoxId` in [0,111], `group=globalBoxId/14`, `local=globalBoxId%14`; preserve native APIs' local IDs and party sentinels (e.g. `TOTAL_BOXES_COUNT==14` meaning party in `swsh_storage_system.c`), and special box menu IDs 200/201. Never reassign the legacy party sentinel to 112. Explicit typed/validated global-ID APIs and local wrappers stop accidental conflation.
5. Preserve currently selected global box as `14*selectedGroup+native.currentBox`. A2 metadata `activePage` continues to pin the selected **journal group** for backward-compatible on-disk format, but pages disappear from gameplay UI. Native `currentBox` remains 0..13.
6. One global trainer, party, bag, flags, item uniqueness and Pokédex across Kanto/Johto/Hoenn and all future regions. No per-region collection reset or mirror; save/ASLR relocation must rebind native-window pointers after copying (existing `MoveSaveBlocks_ResetHeap` fix), without relocating the R8 arena.

## R8.4A: Capability, packaging and cold boot gate
- Create an explicitly named `XGBA_A2=1 XGBA_R8=1` isolated build (distinct `BUILD_NAME`/output) while leaving the existing A1/A2 builds intact. Reject R8 without A1/A2 at compile time. Runtime must not silently enable RAM for a native-only ROM.
- Extend only the create-new developer ROM tagger/validator (`tools/xgba_a2_rom.py` or companion) to stamp exactly 16 descriptor bytes at `0x0FFFFF00`, verifying no collision with A1 high-ROM asset lanes and preserving final E7 16-byte probe, E6 revision byte 0xBC/complement 0xBD, 256 MiB length and existing native ROM geometry. Refuse overwrites and invalid source tags. Pin binary descriptor in tests, not merely file existence.
- On launch, inspect ROM descriptor and require RAM hardware via *nondestructive save/restore of sentinel cells* at base and upper/lower interior of the new RAM, checking readback; specifically distinguish old E7 open-bus values. Do not touch extended E6 save unless R8 capability is confirmed. The game must visibly fail with a precise “R8 emulator required” compatibility message, not continue with blank PC or prompt to format save. Handle missing/wrong version, no E6 save header, allocation failure, and unexpected RAM reset as fatal before game mutation. The exact earliest boot call must be chosen with `GetSaveBlocksPointersBaseOffset`'s pre-load path in mind.
- Allow valid existing A2 E6 journal saves with unchanged on-disk format; they require no automatic destructive migration. Legacy native-only `.sav` still requires a separately validated explicit create-only migration rather than implicit conversion.

## R8.4B: Canonical collection, synchronization, and transaction gate
- Introduce `xgba_r8_collection.[ch]` (or equivalent narrowly owned module) with a fixed R8 layout, `initialized/healthy/frozen` states and checked APIs: `LoadVerifiedCohort`, `SyncResidentToRam`, `SelectGlobalBox`, `GetGlobalMon/SetGlobalMon`, `EnumerateAll`, `PrepareSave`, `SaveCommitSucceeded`, `InvalidateOnError`. No game code should independently construct a raw pointer into another group's storage.
- Cold boot: A2 `XgbaA2CohortSelect` chooses exact native slot and eight page generations; independently CRC/read ALL eight pages once into R8 RAM, **not** from newest physical records. Validate 34144-byte pages plus box/wallpaper/names/metadata, verify active R8 page byte-for-byte equals native `gPokemonStoragePtr` after native load and ASLR relocation. Only then expose gameplay. Failed page read cannot partially initialize playable data; it must invalidate RAM and refuse Continue, or allow selection of a separately verified older cohesive cohort via existing recovery logic. Never fill missing pages with zeroes.
- Synchronization: native 14-box window is authoritative while it is live; flush it to its R8 group before any global enumeration, box-group switch and save. Crossing group boundaries copies current native group to R8 and next R8 group to native, validates target and updates group/global box atomically. Leave all 112 boxes cached in R8 even if the native active window is momentarily newer. Existing `sA2Pager` data-to-disk page-switch path is retired from gameplay; keep journal code as a file-format backend. A direct `BoxPokemon*` used by legacy callers must not survive switching group without a proven copied hand/selection state.
- Mutations: use checked global IDs; keep exact 80-byte records, forms/fusion fields, shiny data, ability, moves, IV/EV, trainer ID, encryption, item, markings/favorites, all 14 box names and wallpapers per group. Normal write access to inactive groups is direct R8. Make overlapping moves, same-box swap, cross-group multi-move and “mon in hand” operations atomic in RAM. No partial mon loss/duplication if menu is canceled mid-operation.
- Save: BEFORE native Flash write, synchronize native group, compare all 8 cached page records against their exact metadata-pinned committed generations *using RAM/digest snapshots* and stage only changed records into the existing E6 A/B journal. No remote write on ordinary box navigation. Update `XgbaA2TransactionCommit` to take a verified full-collection stage vector and still publish native Flash in the opposite slot and metadata LAST, re-select and validate cohort before reporting Save success. Reuse format, CRC, SHA fingerprint and selected generation checks; never manufacture a new metadata version merely for R8. Stage failures must freeze further saves until clean recovery. A dirty bit alone is insufficient because native code writes through arbitrary direct pointers; pair explicit dirty tracking with a full 273,152-byte pre-save reconciliation/compare.
- Power loss: old committed cohort remains recoverable after interrupted page staging or native Flash write, including after two edits on different groups and second Save. A crash after final metadata commit may legitimately select new cohort, otherwise only old verified cohort. Never overwrite the backup page generation that metadata still needs. An ambiguous final-byte write triggers independent cohort re-selection, not a blind retry.
- Boot/restart, overworld transitions, `MoveSaveBlocks_ResetHeap` (after copying and before heap reset), game reset, soft reset and savestate/rewind must not leave stale native or R8 pointers. Ordinary R8 CPU/rewind tests already pass, but actual Anthology RAM contents plus game state need separate end-to-end tests.

## R8.4C: All 112-box gameplay and UI gate
- Replace `Select+L/R` 8-page control with continuous box 1..112 navigation. Ordinary L/R advances/decrements by exactly one global box across 14->15, 28->29 and 111->0. Display global name and index consistently. Group-boundary changes operate solely on RAM and rebuild/invalidate cached box icons, cursor target, wallpaper, scroll state and any stale pointers. Do not create 112 simultaneous sprites or load 112 backgrounds into EWRAM.
- Update `src/swsh_storage_system.c` and `src/pokemon_storage_system.c` (both UI engines), default box, choose-box grid/menu, cursor restore, deposit/withdraw, item moves, party switches, summary screen and nickname/markings, search and sort, bulk operations, plus capture and gift routing outside PC screens. The visual selector can paginate choices as a UI-only convenience; it must not imply disk-backed storage pages.
- Audit all callers of `TOTAL_BOXES_COUNT`, `GetBoxMonDataAt`, `GetBoxedMonPtr`, `StorageGetCurrentBox`, `SetCurrentBox`, `GetFirstFreeBoxSpot`, and party sentinel IDs. Capture with full party searches all 3360 slots; true all-full returns a visible error and does not lose the caught Pokémon. A media failure must never masquerade as “no space”.
- `CountStorageNonEggMons`, `CountAllStorageMons`, `AnyStorageMonWithMove`, last-three-Pokémon release safety, `src/egg_hatch.c`, held key-item uniqueness (`src/item.c:IsDuplicateKeyClassItem`), daycare and cross-region unique-item rewards must use verified global RAM counting/search APIs (or explicit local-only counterparts) with checked failure semantics. No per-frame 3360-mon scans.
- Reuse favorites as existing `MON_DATA_MARKINGS & (1 << 3)`; preserve legends/mythicals and eggs per existing release rules. Protect last 3 non-egg owned Pokémon across party+all boxes. Bulk release must preflight bag capacity for all selected held-item returns and apply all-or-none in RAM, including 112-box operations; no partial action on `AddBagItem` failure. Single release follows the same policy. Shiny alone is not protection per previous owner choice.

## R8.4D: Adversarial host + real emulator CI gate
- Add host C harness for RAM collection against synthetic byte arrays, asserting all eight group sizes, boundary/overflow checks and every valid global box ID, old/new mirror coherence, active-page ASLR rebind and transaction fault injection.
- Extend A2 source test suite and isolated ARM linker: standard, A1, existing A2 (unchanged), new A2+R8; exact `sizeof` and `offsetof` ABI pins; CPU pointers, 4 MiB arena alignment/capacity; verify 256 MiB ROM final markers. Fix all build isolation hazards where make CPPFLAGS do not invalidate cached object files.
- New GitHub Actions disposable runtime workflow MUST CHECK OUT PINNED `DevElectrum/xgba@4e0f59185e2c7d7ed5333d8adc20e8d3ad94d05c` (not frozen E7) and explicitly compile headless scripting-enabled emulator. Existing frozen-E7 A2 workflow remains a regression for old A2 ROM only; it cannot boot the R8-enabled ROM. Build R8 ROM tagged E6 plus descriptor, create-only synthetic E6 `.sav`, never publish ROM/save.
- Emulate actual in-game PC interactions with valid synthetic `BoxPokemon` (not arbitrary fake bytes), distinct identity signatures/PID/OT/items/shiny/favorites/forms in box1, box14, box15, box28, box29, box112; navigate UI across every group boundary; move records, update held items, rename/re-wallpaper, save twice, exit the entire emulator twice, independently audit disk cohort and reopen same records and global box selection. Validate source slot empty after move and destination exact byte match; no duplication, no missing records.
- Inject interruption at each important boundary: mid-E6 page write/CRC, mid-native sector, after native slot before metadata, after final metadata marker, corrupt metadata copy, corrupt latest page A/B, partially initialized 16 MiB E6, wrong descriptor, wrong emulator E7, truncated file, wrong RTC trailer, saver called after a failed previous save. Verify last committed cohort or explicit stop, never a false success/blank collection.
- Runtime bounds: 0 E6 journal page I/O on box navigation; max two 34,144-byte native<->R8 copies per group transition; no 16 MiB full scan; normal gameplay no per-frame global scan; 273,152 bytes maximum one pass per save for untracked direct-pointer dirty detection, journal writes only changed groups. Measure CPU cycles/headless wall, emulated frames for boot, 14->15 and 111->0, and actual 5x performance on disposable equivalent routes. Do not invent FPS or pretend host wall time equals GBA frame latency. A material slowdown or user-visible blocking opens an optimization task *before* final acceptance.

## Proposed implementation order / stop conditions
1. **R8.4A** pin R8 emulator, build+tag handshake, reject old emulator, first RAM read/write and 8-page cold hydrate.
2. **R8.4B** full RAM collection/mirror, global-address APIs, save atomicity and corruption tests, two populated cold-restart generations.
3. **R8.4C** continuous 1..112 UI and all gameplay/global operations/capture, full inventory-held-item correctness, no media reads on navigation.
4. **R8.4D** adversarial CI with real XGBA, cold disk audit, fault injection, throughput and no-regression gates.
5. **R8.4E** cross-region/persistence regressions, handoff and one postponed disposable-owner acceptance.

Stop only for a genuine impossible-to-resolve external dependency or data-loss risk. Fix routine source/compiler/test issues without asking the owner. R8.4 is **not complete** merely because RAM allocation works, 112 empty boxes can be displayed, or a native save counter advances. Exact populated end-to-end preservation is mandatory.
